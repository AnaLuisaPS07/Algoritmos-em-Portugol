Tive muita dificultade e dúvidas quanto aos "Se... Senao...FimSe".
Na minha percepção, o último FimSe em cima de "Senao // acesso restrito" estava fechando o 1° Se, 
e se fosse o caso, não faria sentido esse Senao funcionar, 
porém, o FimSe que fecha o 1° Se na verdade é aquele que está logo acima de FimAlgoritmo

Vou deixar abaixo umas explicações a respeito:



## Aninhamento Condicional
O funcionamento de Se...Senao...FimSe em pseudocódigo ou em muitas linguagens de programação está ligado ao conceito de aninhamento. 
Cada Senao está relacionado ao Se mais próximo que ainda não foi fechado por um FimSe.

Vamos visualizar isso com um exemplo simplificado:

Estrutura de Blocos

Se (condicao1) entao  // Se1
   // Bloco 1
   Se (condicao2) entao  // Se2
      // Bloco 2
   FimSe  // Fecha Se2
   // Ainda dentro de Se1
Senao  // Relacionado ao Se1, não ao Se2
   // Bloco 3
FimSe  // Fecha Se1


Aplicação no Seu Código
No seu código:

Primeiro Se:
Se (nome <> "xptorestrito") entao
    // Código relacionado ao menu e opções
Blocos internos (aninhados):
Dentro desse primeiro Se, há outros Se que tratam das diferentes opções de menu (opcao = 1, opcao = 2, etc.).

FimSe para Blocos Internos:
Cada bloco de opções termina com um FimSe, que fecha cada um dos Se aninhados, mas não fecha o primeiro Se (nome <> "xptorestrito").

Senao (acesso restrito):
Após todos os FimSe que fecham os blocos internos, há o Senao que está diretamente relacionado ao primeiro Se.

A Chave:
O FimSe que fecha um bloco interno não afeta o primeiro Se.
Somente o FimSe correspondente ao primeiro Se encerra sua lógica.
O Senao que aparece depois dos FimSe internos continua relacionado ao primeiro Se, 
porque ele é o Senao que ainda está "aberto" ou esperando por um Senao relacionado ao primeiro Se.


##Em Resumo:
Os FimSe que fecham os blocos internos (as condições baseadas em opcao) não encerram o primeiro Se. 
Apenas o FimSe específico que está logo após o Senao (acesso restrito) faz isso.
O FimSe que fecha o primeiro Se (nome <> "xptorestrito") entao é aquele que está logo acima do fimalgoritmo.

Se (nome <> "xptorestrito") entao
    // Código relacionado ao menu e opções
    
    Se (opcao = 1) entao
        // Lógica para opção 1
    FimSe
    
    Se (opcao = 2) entao
        // Lógica para opção 2
    FimSe
    
    // Outras opções...

Senao // acesso restrito
    // Lógica de acesso restrito

FimSe  // <-- Este fecha o primeiro Se (nome <> "xptorestrito")
fimalgoritmo


Portanto, o Senao (acesso restrito) está diretamente relacionado ao primeiro Se, 
e funciona corretamente, porque o primeiro Se ainda não foi fechado antes do Senao ser encontrado
